# AI 前沿深度分享

为每个工作日举行信息交流的开发与算法团队准备报告；用户约每月报告一次。目标是拓宽视野，并提炼可以借鉴的技术。每次深入一个技术问题，可结合一篇核心材料及少量相关材料。

## 已确定的偏好

- 领域：Agent／AI 应用、模型训练与后训练、多模态。根据本次材料质量选题，无需在一场报告覆盖所有领域。
- 来源：接受英文材料，中文汇报。优先博客、论文、技术社区和研究者账号；将 Datawhale、机器之心纳入发现来源。不巡检代码仓库或开源热榜，不要求阅读实现或运行项目。
- 流程：先给三个候选，等待用户选定，再写完整报告。
- 报告：中文 Markdown，正文讲授二十分钟，不包含讨论。直接从技术问题展开，去掉“本周发生了什么”和新闻速览环节。
- 深度：机制、示例、关键实验；数学以解释方法所必需的程度为限，避免连续推导。
- 配图：最终文章统一使用可见的配图占位符，原图由用户后期截取添加。按报告格式提供出处、原图定位、截取范围、图注与讲解要点。
- 备稿：用户只有三十分钟消化材料。报告本身应足以理解和讲解，不依赖通读长论文或复现项目。

后续明确要求优先于这些默认值。沿用已知偏好，不在每次调用时重新访谈。

## 1. 确定检索范围

使用用户的时区，未指定时为 Asia/Shanghai。未给报告日期时，以执行日为基准。默认检索窗口为截至检索日、含当日在内的七个自然日，输出明确的起止日期及检索截止时间。未来报告日期只表示计划日期，可核验材料仍截至当前；过去日期的回溯报告以该日截止。

“新”按原始发布或实质性更新判断，分别记录事件／论文日期与解读文章日期。旧论文被近期转载，不自动成为本周进展；若近期确有新评测、方法修订等，明确新的部分。旧材料可用于背景，并标注为背景。

如果当前聊天已有用户选定的候选或明确指定的主题，进入第 3 步；否则进入第 2 步。可使用当前项目已有的候选文件与报告记录去重，只有实际可访问记录才能作为“团队已讲过”的依据。

## 2. 检索并提出候选

读取 [来源与核验](references/sources.md)，用实时检索发现材料并打开原文。覆盖上述三个领域及用户偏好的中文渠道；搜索摘要用于发现，不替代阅读全文的关键部分。检索范围是来源池加主题搜索，不要求穷尽所有网站。

合并同一工作的不同转载。以新意、技术可迁移性、证据质量、讲解空间筛选；热度只作发现信号。优先能以问题、方法、证据讲成一条线，且用户能在短时间内掌握的主题。

输出三个候选，每个候选包含：

1. 问题式标题与所属领域。
2. 一句解释所解决的技术瓶颈，以及核心方法的新意。
3. 时间依据：新进展日期、解读日期（如不同）、属于窗口内进展还是背景。
4. 原始材料及必要解读的直接链接；说明一手材料是否可读。
5. 可以借鉴的技术思路、适用条件，以及可展开的二十分钟主线。
6. 证据的主要不足与用户三十分钟备稿的难点。

给出推荐顺序和简短理由，推荐一项。候选文件写入 `reports/YYYY-MM-DD/candidates.md`，向用户提供链接，并请用户选择编号。此阶段到候选为止，等待选择后继续。

候选不足三个时，给出实际符合条件的数量及缺口，不用重复选题凑数。需要扩大时间窗口时，提出明确范围供用户选择；不把较早工作伪装为近一周进展。没有实时检索能力时，说明限制，使用用户提供的材料，或等待恢复检索，不声称已经获取最新信息。

## 3. 深入选定主题

打开核心原始材料，读取方法、实验与局限的相关部分；按需要补读背景与解读。围绕核心结论建立证据：出处、章节／图表、条件和限制。保留原始方法名称，统一中文术语。

用一个贯穿始终的示例解释输入、关键步骤、输出，以及相对已有方法改变了什么。选择最能检验机制的实验，尤其关注对照和消融；没有消融时说明缺失，按材料实际能够支撑的程度表述。

区分作者报告、独立验证与讲者推断。分析借鉴价值时给出适用前提与验证方法；团队具体业务未知时，使用明确标为假设的场景，不替用户编造业务需求。

## 4. 形成报告与备稿路线

读取 [报告结构与备稿](references/report-format.md)，生成：

- `reports/YYYY-MM-DD/<topic-slug>.md`：可直接用于讲授的完整 Markdown 报告，附证据来源与三十分钟备稿路线。
- `reports/YYYY-MM-DD/prep.md`：该次报告的独立备稿路线，包含报告相应章节的链接。若本目录已有其他主题，使用 `<topic-slug>-prep.md`。

所有输出以当前任务工作目录为根；已有不同内容时使用有意义的主题名或版本名保留文件。需要跨聊天继续时，从候选或报告文件恢复状态。用户只要求聊天内输出时，尊重该形式。

交付前检查：讲授时长合计二十分钟、没有新闻速览或讨论时段；技术机制能跟随示例讲清；关键数值有条件和来源；局限与推断可辨；配图使用统一占位格式，已核验的原图位置可追溯，待核验处明确标注；备稿路线合计三十分钟。读完正文应能解释“解决什么、怎样解决、证据如何、可以借鉴什么”。不以堆积资料达到时长。

交付时给出报告、备稿文件链接与阅读起点。仅说明已做的检索和核验，时长标为估计；没有试讲或复现时不声称已验证讲授时间或实验结果。后续修改用户指定部分，并相应校准时长与备稿路线。
