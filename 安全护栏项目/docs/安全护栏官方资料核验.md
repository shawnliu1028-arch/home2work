# 智能座舱 Agent 安全护栏：官方资料核验

核验日期：2026-10-14（中国标准时间）。范围：供应商 API 的用户输入、模型输出检测与流式接入。用户已确认优先试用阿里云、涉及车控、回答会流式播报。以下是公开官方文档核验，未开通服务、未发送真实审核请求、未核验企业合同或实际账户配额。

## 1. 推荐预研路径及产品边界

**建议新项目优先验证阿里云 AI 安全护栏的 MultiModalGuard；保留供应商适配层。** 阿里官方将“安全护栏”和“内容安全增强版”分列；新客接入指南建议直接使用多模态 API，已有 PLUS 客户可升级 SDK 走兼容文本接口。前者包含提示词攻击、敏感数据等防护维度，不能仅凭旧内容标签认定具备相同能力。[产品系列](https://help.aliyun.com/zh/product/28415.html)、[新文本接入指南](https://help.aliyun.com/zh/document_detail/2875414.html)

| 接入路线 | 操作与服务编码 | 定位 |
|---|---|---|
| 新 AI 安全护栏 | `MultiModalGuard`；输入 `query_security_check_pro`，输出 `response_security_check_pro`；也列有 `query_security_check` / `response_security_check` | 新项目主选待验证路线 |
| 新安全护栏的文本兼容路线 | `TextModerationPlus`；`query_security_check` / `response_security_check` | 已有 PLUS SDK 接入可评估升级 |
| 内容安全增强版 PLUS | `TextModerationPlus`；`llm_query_moderation` / `llm_response_moderation` | 旧产品基线，不与新产品结果契约混用 |

第一、二行对应[多模态 API](https://help.aliyun.com/zh/document_detail/2937221.html)、[文本兼容 API](https://help.aliyun.com/zh/document_detail/2875414.html)；第三行对应[PLUS 服务](https://help.aliyun.com/zh/document_detail/2671445.html)。

## 2. 新安全护栏 API 必须核对的契约

MultiModalGuard 的 `ServiceParameters` 是 **JSON 字符串**，单次文本上限 2000 字符；默认账户 QPS 50（文件模态 10）。流式审核需 `chatId` 标识一轮交互，`done` 建议标明是否最后一片。`accountId` 的上下文累计需单独开通，否则仅做身份标识。返回读取 `Data.Suggestion` 和 `Data.Detail[]`，后者含 `Type`、`Level`、`Suggestion`、`Result[]`；标签在 `Result[].Label`。建议值为 `block/pass/watch/mask`，多维合并优先级依次为上述顺序。[多模态 API](https://help.aliyun.com/zh/document_detail/2937221.html)

下面是**本项目自行整理的参数结构示意**，不是实测请求或 SDK 全量代码；该对象交给 SDK 前须将 `ServiceParameters` 序列化为字符串，凭证与签名由 SDK 处理：

```json
{
  "Service": "query_security_check_pro",
  "ServiceParameters": "{\"content\":\"请把空调调到24度\",\"chatId\":\"turn-001\",\"dataId\":\"turn-001-input\"}"
}
```

SDK 官方示例使用 `MultiModalGuardRequest`，将业务参数序列化后传入。Java 示例同时检查 HTTP 状态和响应体 `Code`。凭证应从环境或凭证管理获取；样例中的连接、读取超时只是示例配置，不能直接当作座舱时延要求。[多模态 SDK](https://help.aliyun.com/zh/document_detail/2937220.html)

**结果不能跨 API 混用。** 文本兼容接口有 `Data.RiskLevel`、`SensitiveLevel`、`AttackLevel`，以及 `Result`、`SensitiveResult`、`AttackResult`；它们分别表示不同风险维度。`RiskLevel` 为 `high/medium/low/none`，内容标签置信分为 0–100，部分标签无分值。`Description` 是说明文字，不适合作为策略键。[文本兼容 API](https://help.aliyun.com/zh/document_detail/2875414.html)

建议统一成自有结果：`transport_status`、`inspection_status`、`decision`、`dimensions`、`labels`、`provider_request_id`、`policy_version`。供应商错误或结果缺失转为 `UNKNOWN`，禁止映射为 `PASS`；这是工程建议，不是供应商字段。

## 3. 流式播报应先审核再播放

阿里新流式方案要求内容经审核确认无风险后透出，提供固定字符切片与滑动窗口两种方式。高性能服务 `response_security_check_hp` 推荐用于固定字符切片，并要求 `chatId`、`done` 关联切片。文档“尽量控制在 100 ms 以内”是推荐目标，未提供该项目实测延迟或合同保证。[新流式审核方案](https://help.aliyun.com/zh/document_detail/2980054.html)

**座舱设计建议：** 模型增量 → 本地缓冲 → 调用审核 → 通过后加入 TTS 队列；命中、超时、未知结果时停止未播内容并使用本地固定提示。按自然句及长度限制切片是一种可测试方案，未找到阿里要求“必须等完整句”的官方说明。已播放的音频无法真正撤回，因此不能把“先播后审、事后截断”视作同等安全能力。还需测试跨片组合风险，先前通过的片段不保证拼接后的语义通过。

阿里 MSE 网关现成插件开启输出检测会把流式转换为非流式；故不能直接假定接上插件即可保留现有流式体验。[MSE AI 内容安全](https://www.alibabacloud.com/help/en/mse/user-guide/ai-content-security)

旧 PLUS 路线用 `sessionId` 关联同一输出流增量片段，不能同时传 `accountId`；流式页上部写输出关联审核不超过 5000 字，但下方 API 参数表残留较小长度说明。新旧接口的会话参数与长度规则不能直接互换。[旧流式审核](https://help.aliyun.com/zh/document_detail/2642626.html)

## 4. 异常和时延不是“通过”

官方新文本接口错误表：`400` 参数错误；`408` 权限/账户状态拒绝；`500` 服务临时错误；`581` 审核超时；`588` 超频。特别注意 `408` 在该业务表中不是超时，不能用普通 HTTP 名称推断。官方建议服务错误或超时重试、限流时降低频率。[文本兼容 API 错误表](https://help.aliyun.com/zh/document_detail/2875414.html)

工程建议：同时区分网络异常、HTTP 状态、业务 `Code`、结果结构校验；限次数且受整轮截止时间约束的重试；流式片段按序审核、按序释放。重试若会重复累计切片需先确认供应商幂等机制。失败降级为预先审核的提示，车控不得因护栏不可用而默认执行。预算需通过网络实测得到，不在此写死 100 ms 或 300 ms。

## 5. 旧 PLUS 可作内容检测基线

PLUS 支持中文、英文，含色情、暴恐、违禁、歧视辱骂、隐私等细分内容标签；默认输入 2000 字、输出 5000 字、100 QPS。阈值在控制台配置，没有适用于所有项目的固定分值。页面标签数量存在“60+”与“30+”两种描述，应以实际服务配置为准。[PLUS 官方说明](https://help.aliyun.com/zh/document_detail/2671445.html)

其官方正常响应的核心结构为：

```json
{"Code":200,"Data":{"Result":[{"Label":"nonLabel"}],"RiskLevel":"none"},"Message":"OK","RequestId":"AAAAAA-BBBB-CCCCC-DDDD-EEEEEEEE****"}
```

来源：[PLUS 官方正常响应](https://help.aliyun.com/zh/document_detail/2671445.html)。它只是文档例子，`Code=200` 表示成功返回检测结果，是否放行还要读结果；不存在通用 `Labels` 数组。预研阶段记录实际返回样本后再写解析器。

## 7. 文本护栏不等于车辆动作授权

OWASP 说明提示词注入可来自用户，也可来自网页、文件或其他外部内容；过滤不能被视为绝对防止注入的保证。建议使用明确的外部内容边界、输出格式校验、最小权限和对抗测试。[OWASP LLM01:2025](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

OWASP Excessive Agency 指南建议把授权实施在下游系统，而不让模型决定是否有权限，并逐次验证请求。[OWASP LLM06:2025](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)

据此提出**座舱架构建议**：车控工具执行前，由独立、确定性的策略服务检查工具白名单、参数范围、用户身份/座位权限、实时车辆状态、动作风险与必要确认，之后再交给车控网关。由车型和车控团队定义并审批真实规则；本报告不主张任意车速阈值或车规认证结论。正常措辞的“开门”也可能在车辆状态下不允许；内容审查通过不能替代动作授权。

## 8. 与供应商确认及 PoC 实测清单

1. 选定地域、开通 SKU、实际 `Service` 编码、SDK 版本和有效防护维度。在线测试文档还有 `query_guard_pro_ec` 等名称，须确认与 API 编码的对应关系；不要按显示名称猜服务参数。
2. `response_security_check_hp` 是否已开通、所在地域、支持接口和真实配额。它在流式方案列出，却未在此次多模态 API 枚举表列出。
3. `sessionId` 精确生命周期。多模态文档同页一处说多轮会话，另一处说同一流式响应，必须确认并通过多轮、取消、重试测试验证隔离。
4. `accountId` 上下文功能是否单独开通；上下文窗口、保留时间、拼接方式、调用顺序与重试幂等性。本次未见充分公开定义。
5. 超限返回行为、Unicode 字符计量、空字符串/最后尾片/只有 `done` 的支持、必要字段缺失时的规则。本次不推断未说明的 API 行为。
6. 记录实际返回 JSON 并核对大小写、字段可选性、未知标签及开启维度。新文本样例含 JSON 排版瑕疵，别直接复制全量示例作为测试夹具。
7. 实测普通请求和并发流式审核的 P50/P95/P99、超时/限流率、误拦/漏检率；用中文口语、ASR 同音错词、跨片组合和座舱车控样本评估。
8. 向采购/安全团队确认服务计费与数据处理条款；本报告未作价格预测、数据驻留或法律合规结论。

第 1 项命名线索来自[官方在线测试说明](https://help.aliyun.com/zh/document_detail/2872709.html)；其他待确认项由上文 API 差异、公开文档缺失和该项目流式车控场景形成。
